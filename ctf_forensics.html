Hex dump своими руками

def hexdump(data, length=32, width=16):
    """Аналог xxd/hexdump на чистом Python."""
    for i in range(0, min(length, len(data)), width):
        chunk = data[i:i+width]
        # hex часть: 89 50 4e 47 ...
        hex_part = ' '.join(f'{b:02x}' for b in chunk)
        # ascii часть: печатные символы или '.'
        ascii_part = ''.join(
            chr(b) if 32 <= b < 127 else '.'
            for b in chunk
        )
        print(f'{i:08x}  {hex_part:<{width*3}}  {ascii_part}')

# Использование:
with open('task1.bin', 'rb') as f:
    data = f.read()
hexdump(data, length=32)

Пройти по коду построчно.

f'{b:02x}'

Форматная строка: b — это int, :02x — минимум 2 символа, лидирующие нули, шестнадцатеричный формат. Например, 10 → '0a', 255 → 'ff', 5 → '05'.

' '.join(...)

Объединяет список строк через пробел. Из ['89','50','4e','47'] делает '89 50 4e 47'.

ascii_part

Генераторное выражение: chr(b) if 32 <= b < 127 else '.' — переводим в символ если печатный, иначе точка.

width*3

Почему умножаем на 3: каждый байт = 2 hex-символа + 1 пробел. То есть ширина поля — 16 байт × 3 = 48 символов.

def detect_type(data):
    """Определяем тип файла по magic bytes."""
    signatures = [
        (b'\x89PNG\r\n\x1a\n', 'PNG'),
        (b'\xff\xd8\xff',      'JPEG'),
        (b'GIF87a',            'GIF (87a)'),
        (b'GIF89a',            'GIF (89a)'),
        (b'BM',                'BMP'),
        (b'PK\x03\x04',        'ZIP'),
        (b'%PDF',              'PDF'),
        (b'Rar!\x1a\x07',      'RAR'),
        (b'7z\xbc\xaf\x27\x1c', '7z'),
        (b'\x7fELF',           'ELF (Linux EXE)'),
        (b'MZ',                'EXE (Windows)'),
    ]
    for sig, name in signatures:
        if data.startswith(sig):
            return name
    return 'Unknown'

# Использование:
with open('task1.bin', 'rb') as f:
    data = f.read()
print(detect_type(data))   # 'JPEG'

Strings — извлечение ASCII

В любом бинарном файле между "мусорными" байтами часто прячутся печатные ASCII-строки — имена функций, пути, сообщения, иногда флаги. Извлечение этих строк — первый шаг в анализе.

Идея

Проходим по всем байтам, подряд идущие печатные ASCII (32–126) собираем в строку. На непечатном байте обрываем.

Минимальная длина — обычно 4 символа (чтобы отсеять случайные совпадения).

Печатный ASCII — байты 32–126 (от пробела до тильды ~). 0–31 — управляющие (Enter, Tab), 127 — DEL.

Визуально

data = b'\x00\x00Hello, World!\x00\xffctf{hidden}\x00\x01'
       ↑↑↑                 ↑↑↑                  ↑↑↑↑↑
       непечатные          разделитель           разделитель

strings = ['Hello, World!', 'ctf{hidden}']
В CTF Строки чаще всего в ASCII. Иногда в UTF-8 — для начала достаточно ASCII. Флаги обычно в формате ctf{...} — все символы печатные ASCII.

Объяснить идею "печатный ASCII". Это байты 32–126 (пробел до тильды ~). Байты 0–31 — управляющие (Enter, Tab, BEL), 127 — DEL, 128+ — зависит от кодировки (UTF-8, Latin-1 и т.д.).

В CTF

Строки чаще всего в ASCII, но иногда в UTF-8. Для начала достаточно ASCII — флаги ctf{...} всегда ASCII.

def extract_strings(data, min_len=4):
    """Аналог утилиты strings на чистом Python."""
    result = []
    current = []
    for b in data:
        if 32 <= b < 127:        # печатный ASCII
            current.append(chr(b))
        else:
            # конец строки — сохраняем если длинная
            if len(current) >= min_len:
                result.append(''.join(current))
            current = []
    # не забудем последнюю
    if len(current) >= min_len:
        result.append(''.join(current))
    return result

# Использование:
with open('task2.bin', 'rb') as f:
    data = f.read()

strings = extract_strings(data)
for s in strings:
    if 'ctf{' in s:
        print('Flag found:', s)

Логика

current — накапливаем печатные символы. На непечатном — добавляем в результат если длина ≥ min_len.

Важно! Не забыть обработать последнюю строку после цикла. Если файл кончается печатными символами, без этого блока они потеряются.

Перевод числа в символ: chr(32)=' ', chr(65)='A', chr(126)='~'.

Task 7 — самый сложный момент это правильно найти конец ZIP.

EOCD — End Of Central Directory

Сигнатура PK\x05\x06, длина 22 байта + комментарий длиной в поле по смещению 20 (2 байта, little-endian). struct.unpack('<H', ...) — именно little-endian.

Почему '<H'

< = little-endian, H = unsigned short (2 байта). ZIP использует little-endian (как x86), в отличие от PNG который использует big-endian (>I).

PNG формат — структура

PNG = 8-байтная сигнатура + последовательность chunks. Каждый chunk: 4 байта длина + 4 байта тип + данные + 4 байта CRC.

PNG file: ┌───────────────────────────────────────┐ │ Signature (8 bytes: \x89PNG\r\n\x1a\n) │ ├───────────────────────────────────────┤ │ Chunk: length(4) type(4) data(N) CRC(4)│ IHDR ├───────────────────────────────────────┤ │ Chunk: length(4) type(4) data(N) CRC(4)│ tEXt ├───────────────────────────────────────┤ │ Chunk: ... │ IDAT (×N) ├───────────────────────────────────────┤ │ Chunk: length=0 type=IEND │ IEND └───────────────────────────────────────┘

Chunk types

  • IHDR — заголовок (ширина, высота, битность)
  • PLTE — палитра (для индексных)
  • IDAT — сжатые пиксели (zlib), может быть несколько!
  • IEND — конец файла (длина 0)
  • tEXt — текстовые метаданные (ключ\x00значение)
  • iTXt — Unicode текст
  • zTXt — сжатый текст
tEXt-чанк = ключевое поле для сокрытия данных в CTF. Формат: keyword\x00value. Пример: Comment\x00ctf{hidden_here}.

Подчеркнуть: IDAT может быть несколько — часто в CTF задачах просят посчитать их количество (это task 3 сегодня).

tEXt-чанк

Ключевое поле для сокрытия данных. Формат: keyword\x00value — ключевое слово, нулевой байт как разделитель, значение. Пример: Comment\x00ctf{hidden_here}.

Standard keywords

Title, Author, Description, Copyright, Creation Time, Software, Disclaimer, Comment (любимый для CTF), Source, Warning.

CRC

CRC32 — контрольная сумма данных chunk. Для forensics обычно игнорируем, но можно проверять если хотим убедиться что данные не повреждены.

Парсинг PNG chunks в Python

import struct

def parse_png_chunks(data):
    """Парсит PNG файл на чанки.
    Возвращает список (type, data, offset)."""
    chunks = []
    if not data.startswith(b'\x89PNG\r\n\x1a\n'):
        return chunks   # не PNG
    pos = 8   # пропускаем сигнатуру
    while pos < len(data):
        if pos + 8 > len(data):
            break
        length = struct.unpack('>I', data[pos:pos+4])[0]
        ctype = data[pos+4:pos+8]      # 4 байта тип
        cdata = data[pos+8:pos+8+length]
        # CRC 4 байта после данных (не проверяем)
        chunks.append((ctype, cdata, pos))
        if ctype == b'IEND':
            # всё что после IEND — дописано
            appended = data[pos+12+length:]
            if appended:
                chunks.append((b'__APPENDED__', appended, pos+12+length))
            break
        pos += 12 + length   # length field + type + data + CRC
    return chunks

# Использование:
with open('image.png', 'rb') as f:
    data = f.read()
for ctype, cdata, offset in parse_png_chunks(data):
    print(ctype.decode(), len(cdata), 'bytes')

>I = big-endian unsigned int (4 байта). PNG использует big-endian.

Цикл пока не IEND — читаем chunk. Если после IEND что-то есть — это дописанные данные (важный случай для CTF).

После IEND добавляем фиктивный chunk типа __APPENDED__ с дописанными данными. Удобно для отслеживания.

Чтение 4 байтов как числа. '>' = big-endian (старший байт первым), 'I' = unsigned int (4 байта). PNG использует big-endian, в отличие от ZIP (little-endian).

12 = 4 (length field) + 4 (type) + 4 (CRC). + length — это сами данные chunk. Типичная ошибка: забыть +length, тогда цикл уйдёт в бесконечность.

__APPENDED__ трюк

После IEND добавляем фиктивный chunk типа '__APPENDED__' с дописанными данными. Это удобно — дальше в коде проверяем if ctype == b'__APPENDED__' и обрабатываем отдельно.

Offset

Сохраняем offset на случай если нужно знать позицию chunk в файле (например, для отладки или поиска конкретного места).

ZIP формат — структура

ZIP = последовательность Local File Headers + Central Directory + End Of Central Directory (EOCD).

ZIP file: ┌─────────────────────────────────────────┐ │ Local File Header 1 (PK\x03\x04) │ │ File data 1 │ ├─────────────────────────────────────────┤ │ Local File Header 2 (PK\x03\x04) │ │ File data 2 │ ├─────────────────────────────────────────┤ │ ... │ ├─────────────────────────────────────────┤ │ Central Directory (PK\x01\x02) │ │ - Запись для файла 1 │ │ - Запись для файла 2 │ ├─────────────────────────────────────────┤ │ EOCD (PK\x05\x06) │ │ - Может быть archive comment (до 64KB) │ └─────────────────────────────────────────┘

Python zipfile делает всё сам

ZipFile.read(name) — находит local header, читает данные, декодирует. Ничего парсить вручную не надо.

Зачем тогда знать структуру? Чтобы: 1) находить конец ZIP (EOCD) для multi-file задач; 2) понимать что комментарий — это поле в EOCD.

Сигнатуры

  • PK\x03\x04 — Local File Header
  • PK\x01\x02 — Central Directory entry
  • PK\x05\x06 — EOCD (End Of Central Directory)

Объяснить структуру — но подчеркнуть что в Python нам не надо парсить это вручную. zipfile всё делает сам.

Разбираем задачу вместе

Задача. Дан image.png. Это валидная картинка. Но внутри спрятан ZIP-архив с флагом. Найдите флаг.

Пошаговый разбор

  1. Открываем файл: data = open('image.png', 'rb').read()
  2. Парсим PNG chunks: chunks = parse_png_chunks(data)
  3. Смотрим — есть ли chunk с типом __APPENDED__?
  4. Да! Берём appended bytes.
  5. Проверяем сигнатуру: appended.startswith(b'PK\x03\x04') → True, это ZIP
  6. Открываем как ZIP: zf = zipfile.ZipFile(io.BytesIO(appended))
  7. Читаем флаг: zf.read('flag.txt').decode()

with open('image.png', 'rb') as f:
    data = f.read()
chunks = parse_png_chunks(data)
for ctype, cdata, _ in chunks:
    if ctype == b'__APPENDED__':
        if cdata.startswith(b'PK\x03\x04'):
            zf = zipfile.ZipFile(io.BytesIO(cdata))
            print(zf.namelist())
            # ['flag.txt']

            # ctf{found_in_appended_zip}
        break

f-string в решении 3

regex на bytes
