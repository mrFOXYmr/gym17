    Теория. Принцип FORENSIC-подхода

  • Сначала определить тип файла — это диктует инструмент.
  • strings — быстрые читаемые строки; binwalk — вшитые архивы/файлы.
  • Метаданные (EXIF) — скрытые поля: автор, GPS, комментарий.
  • Часто флаг «зашит» в скрытой области, невидимой обычным текстом.

    • Тема 14.1. FORENSIC — анализ файлов и памяти

    Приёмы:

    file mystery        # тип файла
strings mystery | grep -i flag
xxd mystery | head  # hex-взгляд
binwalk mystery     # вшитые файлы/архивы

    Что ищем: скрытые данные, метаданные, стеганографию, EXIF.

    FORENSIC: порядок действий

  • Определить тип файла (file).
  • Прочитать строки (strings) — быстрый поиск флага.
  • Посмотреть вшитые архивы (binwalk).
  • Метаданные/EXIF.
  • Иногда — hex-анализ (xxd).

    • ПРАКТИКА А. FORENSIC

  • file — определи тип учебного файла.
  • strings | grep flag — найди секрет.
  • binwalk — вшитые архивы.
  • Метаданные (EXIF) картинки — что прочитать?

    • Цель — добыть «флаг/секрет».

    Тема 14.2. OSINT — открытые источники

  • По подсказкам искать информацию в открытых данных.
  • Источники: поиск, соцсети, профили, метаданные, карты.
  • Алгоритм: собрать все «хвосты» → связать → найти флаг.

    • OSINT: цепочка фактов

  • Один факт (ник) → профиль.
  • Профиль → город/даты/первые посты.
  • Метаданные медиа → где снималось.
  • Связываем → искомый секрет/флаг.
  • План ДО поиска экономит время и не даёт увестись в сторону.

    • ПРАКТИКА Б. OSINT (упражнение на логику)

  • Взять гипотезу: «ник + город». Составить план поиска.
  • Определить 3 источника и что из них взять.
  • Собрать цепочку фактов к флагу (учебная задача).

    • Без реальных атак — только моделирование.

    Тема 14.3. PPC — программирование для данных

    Автоматизировать обработку большого объёма (логи, трафик).

    from collections import Counter
ips = [...]
print(Counter(ips).most_common(3))

    ПРАКТИКА В. PPC (Python)

  • Прочитать лог, собрать все IP через regex.
  • Посчитать количество запросов на IP (Counter).
  • Вывести топ-3.
  • Повторяющиеся шаги — оформить как функцию.

    • Это типичная задача для PPC в CTF и данных НТО.

    РАЗБОР ФЛАГА. Топ-IP по логу

    По логу выше: какой IP самый частый, какой — публичный?

    Ответ

    Самый частый: 192.168.1.10 (3 раза), публичный: 8.8.8.8 (1 раз).

    Флаг-формат: PPC{<частый>-<публичный>} → PPC{192.168.1.10-8.8.8.8}.

    Теория. Почему PPC = «написать скрипт, а не кликать руками»

  • Данных много: логи, трафик, тысячи строк.
  • Ручной подсчёт медленный и с ошибками.
  • Скрипт (regex + Counter) решает за секунды и воспроизводим.
  • PPC в олимпиадах — проверка именно этой автоматизации.

    • Тема 14.4. Связь категорий с олимпиадам

  • PPC — НТО (программирование) и Innopolis/CTF.
  • FORENSIC/OSINT — широко в Innopolis отбор-тур1.
  • ВсОШ практика (файлы) также близка к FORENSIC.
  • FORENSIC ≠ REVERSE: первый про данные/файлы, второй про исполняемые.

    • Практический мини-турнир

    Таски отбор-тур1 Innopolis (FORENSIC + OSINT + PPC) на время.

    Типовые ошибки

  • В FORENSIC не смотрят strings/binwalk — пропускают спрятанное.
  • В OSINT бросаются на поиск без чёткого плана.
  • В PPC делают вручную, а не скриптом.
  • Путают FORENSIC и REVERSE.

    • Резюме: что уносим

  • FORENSIC: file → strings → binwalk → EXIF; принцип «тип задаёт инструмент».
  • OSINT: план → источники → цепочка фактов → флаг.
  • PPC: regex + Counter для автоматизации больших данных.
  • Различие FORENSIC (данные) и REVERSE (исполняемые).
