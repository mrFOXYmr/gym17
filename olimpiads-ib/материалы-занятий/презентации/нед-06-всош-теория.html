    Теория. Зачем кодировать (а не шифровать)

  • Base64/32 не защищают, а представляют данные в тексте.
  • Нужны для передачи/хранения бинарных данных текстом.
  • «Раскрутка» = обратная операция, пока текст читаемый.
  • В олимпиадах — наоборот: данные закодированы многократно.

    • Тема 6.1. Карта теоретических вопросов ВсОШ

  • Порты и протоколы (80/443/22/53...).
  • Linux (~, chmod, iptables).
  • Браузерная безопасность (CSP/CORS/SOP/HSTS).
  • Хеши (SHA-256 = 64 hex).
  • Сетевые правила (iptables).
  • Криптография (перестановка, Base32/64).
  • Угрозы/инциденты (разведка → доступ → закрепление → C2).

    • Тема 6.1b. Угрозы и инциденты (жизненный цикл)

  • Разведка (recon) → сканирование цели.
  • Доступ (exploit) → получение контроля.
  • Закрепление (persistence) → удержание доступа.
  • C2 / командный центр → управление жертвой.
  • В ВсОШ просят восстановить порядок этих фаз.

    • Тема 6.2. Декодирование Base32/Base64

  • Base64 кодирует в 64 символа; Base32 — в 32.
  • Задача ВсОШ «Полимерный контейнер»: данные закодированы НЕ ОДИН раз.
    • import base64
s = input().strip()
while True:
    try:
        s = base64.b32decode(s).decode()
    except Exception:
        break
print(s)
  • «Раскрутка» = повторяем, пока не перестанет декодироваться.

    • Разница алфавитов Base64 и Base32

  • Base64: A–Z a–z 0–9 + / и оконечный =.
  • Base32: A–Z 2–7 (без 0/1/8/9), выравнивание = до кратности 8.
  • Как понять, что перед тобой B32: только прописные буквы латиницы и цифры 2–7.

    • Теория. Как выглядит «раскрутка» на практике

    import base64
def unwrap(s):
    while True:
        for fn in (base64.b64decode, base64.b32decode):
            try:
                s = fn(s).decode(); break
            except Exception:
                continue
        else:
            break
    return s
  • Пробуем каждый алфавит; если падает (bad padding) — пробуем следующий.
  • Как только ни один не декодируется — текст чистый, остановились.
  • Защита от вечного цикла: try/except и условие выхода.

    • ПРАКТИКА А. Раскрутка кодирования

  • Строку закодировать в Base64 → декодировать обратно.
  • Двойное кодирование (Base64+Base64) → раскрутить циклом.
  • Микс: Base64 затем Base32 → раскрутить, пробуя оба.
  • Написать универсальную «раскрутку» с try/except.

    • Тема 6.3. Формат ответа ВсОШ

  • Ответ-флаг: vsosh{...}. Сдать ровно эту строку — иначе 0 баллов.
  • Частая ошибка: лишний пробел/перенос, неверный регистр.
  • Всегда убирать .strip(), приводить регистр перед сдачей.

    • РАЗБОР ФЛАГА. Многослойное кодирование

    Строка VS{...}-формата: раскручиваем до читаемого.

    import base64
s = "S05DVUdWS1NJVlBVR1NLUUpCQ1ZFWFpVR0k9PT09PT0="
print(unwrap(s))   # сколько слоёв? какой результат?
    Ответ

    1-й слой: Base64 → KNCUGVKSIVPUGSKQJBCVEXZUGI======.

    2-й слой: Base32 → SECURE_CIPHER_42.

    Флаг в формате ВсОШ: vsosh{SECURE_CIPHER_42}.

    ПРАКТИКА Б. Работа с данными (пассивный анализ)

  • bytes.fromhex() — восстановить текст из hex.
  • Определить тип файла по сигнатуре (%PDF, PNG, ELF...).
  • strings файл | grep -i flag — поиск секрета.
  • Обратный перевод: текст → hex → base64 → вернуть текст.

    • ПРАКТИКА В. Формат ответа

  • Что отдавать: только строку-флаг, без лишнего.
  • Приведи пример vsosh{...} для найденного «послания».
  • Как избежать ошибок регистра/пробелов.

    • Типовые ошибки

  • Бесконечный цикл в «раскрутке» — нужен try/except и защита.
  • Путают Base32 (A-Z,2-7) и Base64 (+/ и =).
  • Сдают расшифрованное «послание» вместо vsosh{...}.
  • Не приводят регистр/не убирают пробелы перед сдачей.
