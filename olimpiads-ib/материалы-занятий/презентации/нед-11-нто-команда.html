    Теория. Почему командный кейс — это процесс, а не «найти флаг»

  • Кейс = несколько плоскостей сразу: сеть, web, крипто, инциденты.
  • Один человек не успеет всё → важно разделять роли.
  • Оценка включает отчёт: находки без обоснования не считаются полными.
  • Главный навык — координация времени и информации.

    • Тема 11.1. Что такое командный кейс НТО ИБ

    Комплексная задача по ИБ объекта критической инфраструктуры:

  • Расследование инцидентов.
  • Криптографическая защита.
  • Поиск/эксплуатация/устранение web и бинарных уязвимостей.

    • Решение командой; сдаётся отчёт — обязателен.

    Тема 11.2. Роли в команде (2 человека)

    РольЗадачи
    Разведчик/сканерnmap, анализ сервисов, карта сети
    Атакующийэксплуатация web/бинарных уязвимостей
    Криптографрасшифровка, проверка целостности
    Писатель отчётафиксация шагов, оформление

    В паре роли совмещают: один атакует, второй параллельно — крипто + отчёт.

    Тема 11.3. Как строить командный план

    Порядок на

  • Разведка: nmap, что открыто.
  • Атака: web/крипто, поиск флагов.
  • Крипто/инциденты: расшифровки, целостность.
  • Отчёт: шаги + команды + находки + флаги.

    • Координация: роли проговариваем ДО старта.

    Тема 11.3b. Координация без дублей

  • Разделить сервисы: один берёт 80/3000, второй — 3306/22.
  • Помечать «не трогаю» на вектор партнёра.
  • Checkpoint каждые
  • Флаги сразу фиксировать в общий файл отчёта.

    • Тема 11.4. Как писать отчёт

  • По шагам: сканировали → что нашли → как эксплуатировали → что добыли.
  • Прикладывать команды, скрины, флаги.
  • Отчёт оценивается — «найти флаг» без отчёта неполно.

    • Разбор примера (методичка Innopolis тур2)

  • nmap -sV -p- → 80, 3000, 3306.
  • Web → /profile (LFI) → config.js.
  • Дальше root-доступ по методичке.

    • Фиксируем шаги как в отчёте — это образец.

    РАЗБОР ФЛАГА. Структура шага отчёта

    Заполни шаги по образцу:

    [Шаг 1] nmap -sV -p- 10.10.10.2   -> что открыто? куда смотреть?
[Шаг 2] curl .../profile          -> где уязвимость? какой файл?
    Ответ
  • nmap → открыты 80, 3000, 3306; гипотеза web(3000) + БД(3306).
  • /profile → LFI в app.js → файл config.js.

    • Флаг-приём: каждый шаг = команда + вывод + следующий вектор.

    Теория. Зачем фиксировать шаги по ходу

  • Отчёт «по памяти» после игры — потерянные детали и флаги.
  • Фиксация команды+вывода сразу = воспроизводимый путь.
  • Чек-лист в реальном времени: разведка → атака → находка → флаг → следующий вектор.
  • Это экономит пересказ и делает отчёт полным и обоснованным.

    • КОМАНДНАЯ МИНИ-ИГРА (на время)

    Каждой команде — учебная машина (методичка Innopolis тур2 / НТО командный).

    Задание: получить user и root, добыть флаги, написать отчёт.

    Оцениваем: полнота отчёта + добытые флаги.

    Всё на учебных машинах, легально.

    Критерии оценки отчёта

  • Полнота: разведка → атака → крипто → флаги.
  • Доказательность: команды и скрины, а не «нашли флаг».
  • Структура: каждый шаг однозначен и воспроизводим.
  • Отражение флагов и того, что осталось нерешённым.

    • Разбор игры и оценка отчётов

  • Обсудить, что получилось/не получилось по ролям.
  • Сравнить отчёты команд, показать «эталон».
  • Отметить скорость координации и что улучшить к 05.11.

    • Типовые ошибки

  • В паре дублируют работу (оба сканируют, никто не пишет отчёт).
  • Не фиксируют шаги по ходу — отчёт по памяти.
  • Застревают на одной уязвимости, забывая про другие плоскости.
  • Сдают только флаг без обоснования.

    • Резюме: что уносим

  • Командный кейс — процесс: роли, разделение, координация.
  • План на
  • Отчёт обязателен: команда + вывод + следующий вектор.
  • Не фиксировать по памяти — фиксировать по ходу.
