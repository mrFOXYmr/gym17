# Домашнее задание 10 — Web-уязвимости

## Часть A. Таблица признаков
| Уязвимость | Признак | Пример эксплуатации |
|-----------|---------|---------------------|
| LFI | параметр читает файл | `?file=/etc/passwd` |
| SQLi | логин без пароля | `username=admin&password[password]=1` |
| SSTI | ввод попадает в шаблон | `X-Forwarded-For: {{config}}` |
| Race | гонка параллельных запросов | одновременные GET/POST |
| XSS | JS исполняется в браузере | `<script>alert(1)</script>` |

Дополни пустую колонку «чем отличается от соседней» для LFI vs RFI.

## Часть B. Payload-лаборатория (флаг-задачи)
**1. LFI.** Определи, что прочитает запрос:
```
http://<host>/site/board.php?page=../../../../etc/passwd
```
Что мешает прочитать (фильтр на `../`)? Приведи приём обхода с `....//....//` и объясни.

**2. SQLi.** Обход логина через параметризацию массива:
```
username=admin&password[password]=1
```
Почему `password[password]=1` = пароль-проверка возвращает `1` (true)? Что это за уязвимость в Node-фреймворке (похоже на «type juggling»)?

**3. SSTI.** При тесте `{{7*7}}` сервер вернул `49`. Как это подтверждает template injection?
> Флаг подтверждения: `WEB{SSTI_49}` — запиши его после проверки.
