## Теория. Почему порты — это «двери»
- Компьютер слушает множество сервисов сразу.
- Порт — номер «двери», по которой приходит запрос к сервису.
- Зная порт, мы знаем, какой сервис и как к нему подойти.
- В разведке (nmap) первое — определить открытые порты.

## Зачем нужны порты

- Для ВсОШ — прямые вопросы («порт HTTP»), для CTF-NETWORK — чтение трафика по порту.

## Тема 2.1. Памятка портов и протоколов
| Порт | Протокол | Назначение |

| 21 | FTP | передача файлов |

## Как порты встречаются в CTF
- `nmap -sV -p-` показывает открытые порты → «двери» в систему.
- Порты баз данных (3306/5432) важны: найти креды → получить данные/флаг.
- Веб-порт (80/3000/8080) → зайти, смотреть исходники, robots.txt.
- Умение читать поты — первый шаг любой разведки.

## Тема 2.2. Защита в браузере (для ВсОШ)
- **Same-Origin Policy (SOP)** — скрипт с одного origin не лезет в другой.
- **Content Security Policy (CSP)** — whitelist источников, где можно выполнять JS (верный ответ ВсОШ «что запрещает JS из недоверенных источников?»).
- **CORS** — разрешение кросс-доменных запросов по заголовку.
- **HSTS** — принудительный HTTPS.

## Отличие SOP от CORS (важное)
- SOP — *правило по умолчанию* (запрет).
- CORS — *механизм отмены* запрета по явному разрешению сервера.
- В ВсОШ часто проверяют именно противопоставление.

## Тема 2.3. Хеши — база
- SHA-256 даёт фиксированные **32 байта / 64 hex-символа**.
- Зачем: целостность, хранение паролей, цифровые подписи.
- Хеш необратим — в отличие от шифрования (односторонняя функция).
- Лавинный эффект: изменение одного символа полностью меняет хеш.

- Зачем: целостность, хранение паролей, цифровые подписи.

## Теория. Хеш vs шифрование
- **Шифрование** обратимо: есть ключ, можно расшифровать.
- **Хеш** необратим: из результата нельзя восстановить вход (за разумное время).
- Поэтому для паролей хранят хеш: утекла БД — пароль не виден.
- Для целостности сравнивают хеш до/после передачи.

## Теория. Срез строк — как работает
```python
s = "abcde"
print(s[1:4])   # "bcd" — срез от 1 до 4 (не включая 4)
print(s[::-1])  # "edcba" — разворот через шаг -1
print(s[0:3])   # "abc" — первые 3
```
- `s[start:stop:step]` — индексы. Пропущенный start/stop = начало/конец.
- `step` может быть отрицательным → идём назад.
- Срез возвращает **новую строку**, исходная не меняется.

## Теория. Коды символов ord/chr
```python
print(ord('A'))   # 65 — код символа
print(chr(65))    # 'A' — символ по коду
```
- Каждый символ — число (кодовая точка).
- Перевод в код/из кода — база шифров-перестановок и XOR.

## ПРАКТИКА А. Строки (разбор у доски)

s = input().strip()

Срезы `s[a:b:c]`: `a` старт, `b` стоп, `c` шаг. Методы `.count()`, `.lower()`, `.isalpha()`.

## РАЗБОР ФЛАГА. Анализ hex-порта
Задание: первые байты IP-пакета `45 00 .. .. .. .. .. .. .. .. .. .. 04 d2 00 35`.
`src = data[20:22]`, `dst = data[22:24]` — извлекаем порты:
```python
data = bytes.fromhex("4500003a1c4640004006b1e67f0000017f00000104d20035")
src = int.from_bytes(data[20:22], "big")   # ?
dst = int.from_bytes(data[22:24], "big")   # ?
```
::: Ответ
`04 d2` = **1234** (src), `00 35` = **53** → DNS.
Флаг: `NET{<src>-<dst>}` → `NET{1234-53}`.
:::

## Типовые ошибки
- Срез `s[::-1]` путают с `s[:1]` (первый символ) и `s[1:]` (всё кроме первого).
- `ord(char)` уже возвращает int — не нужен `int()`.
- При вводе с пробелами забывают `.strip()`.
- `.count()` считает подстроки — нужен `.lower()` при учёте регистра.
- В пакете путают `--dport`/`--sport` и офсеты 20–24 для TCP/IP.
